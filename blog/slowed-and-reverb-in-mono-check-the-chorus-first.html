Does your slowed + reverb hold up in mono? Check the chorus first

NoDAW Labs · Lacquer Vol. 06

Slowing a beat doesn’t change how it folds to mono. The effects you add after it do. In our test a beat at HalfScrew’s TIME 80 kept the same 0.995 correlation as the original. Its reverb lost 3.46 dB in mono against the dry centre, so the mono version just sounds drier. CHORUS at 100 dropped the correlation to 0.109 and made a steady 500 Hz note swing 32.9 dB in the mono fold.

Headphones, it’s the whole mood: slow, wide, a big hall behind everything. Then it plays off a phone, or one Bluetooth speaker on a shelf, and something’s off. Drier than you remember, or worse, a seasick flutter in the melody that wasn’t there before.

The usual suspect is the slowdown, but slowing isn’t what changes in mono. Varispeed does the same thing to both sides. What changes is the reverb and the chorus you put on after it.

What the reverb and chorus do to the two sides

HalfScrew runs varispeed first, then EQ, reverb, delay, chorus and drive, then a true-peak limiter. The reverb is a fixed 3 s hall built from two different noise bursts, one per side, so its left and right have little in common. The chorus delays each side by about 8.5 ms and sweeps that delay up and down by 3.5 ms at 1.5 Hz, the two sides moving in opposite directions. Each effect knob is a dry/wet crossfade, and both turned on start at 30. The limiter turns both sides down together, so it doesn’t change the balance between them.

We wrote mono_check.py to put numbers on it. It ports the varispeed, the reverb and the chorus from HalfScrew’s source with the EQ flat and WOW at 0, builds an 8-bar beat at 140 BPM with the kick, 808, snare and lead in the middle, and measures three things: how alike the two sides are (correlation), how much level the mix loses when it’s folded to mono, and how much a steady note’s level swings with the chorus on.

# Slowed + reverb in mono: what HalfScrew's varispeed, REVERB and CHORUS do to a mono fold-down.
# Ported from halfscrew.js resample() and halfscrew-fx.js (v=44): 4-point Hermite varispeed (HQ, WOW 0),
# REVERB = convolver with the tool's 2-channel 3 s IR (L->L, R->R, Web Audio normalize), CHORUS = two 8.5 ms
# delays swept +-3.5 ms by a 1.5 Hz sine, opposite sign per side. Each FX amount is a dry/wet crossfade. EQ flat.
import numpy as np
from scipy.signal import butter, sosfilt, fftconvolve
fs = 48000; rng = np.random.default_rng(26); BPM = 140; beat = 60 / BPM

def hermite(y0, y1, y2, y3, f):
    c1 = 0.5 * (y2 - y0); c2 = y0 - 2.5 * y1 + 2 * y2 - 0.5 * y3; c3 = 0.5 * (y3 - y0) + 1.5 * (y1 - y2)
    return ((c3 * f + c2) * f + c1) * f + y1
def varispeed(a, ratio):
    n = int(np.ceil(len(a) / ratio)); pos = np.arange(n) * ratio; i0 = np.floor(pos).astype(int); f = pos - i0
    g = lambda k: np.where((k >= 0) & (k < len(a)), a[np.clip(k, 0, len(a) - 1)], 0.0)
    return hermite(g(i0 - 1), g(i0), g(i0 + 1), g(i0 + 2), f)

def reverb_ir():                                   # halfscrew-fx.js reverbIR(), same LCG seeds and envelope
    L = int(fs * 3.25); ir = np.zeros((2, L)); pre = int(fs * 0.012)
    for c in range(2):
        seed = (0x9e3779b1 ^ ((c * 0x85ebca6b) & 0xffffffff)) & 0xffffffff; lp = 0.0
        for i in range(L):
            seed = (seed * 1664525 + 1013904223) & 0xffffffff; noise = seed / 2147483648 - 1; t = i / fs
            k = 0.9 - 0.82 * np.exp(-t * 1.6); lp = lp * k + noise * (1 - k)
            ir[c, i] = 0 if i < pre else lp * np.exp(-6.9078 * t / 3) * max(0, min(1, (i - pre) / (fs * 0.02))) * 2.2
    p = max(np.sqrt((ir ** 2).sum() / ir.size), 0.000125)       # Web Audio ConvolverNode normalize = true
    return ir * (1 / p) * 0.00125 * (44100 / fs)
IR = reverb_ir()

def chorus(x):                                     # x: (2, n). Per side: delay = 8.5 ms +- 3.5 ms, 1.5 Hz sine
    n = x.shape[1]; t = np.arange(n) / fs; out = np.zeros_like(x)
    for c, sgn in ((0, 1), (1, -1)):
        d = (0.0085 + sgn * 0.0035 * np.sin(2 * np.pi * 1.5 * t)) * fs
        pos = np.arange(n) - d; i0 = np.floor(pos).astype(int); f = pos - i0
        g = lambda k: np.where(k >= 0, x[c][np.clip(k, 0, n - 1)], 0.0)
        out[c] = g(i0) * (1 - f) + g(i0 + 1) * f
    return out

def halfscrew(x, time=100, rev=0, cho=0):
    y = np.array([varispeed(ch, time / 100) for ch in x])
    if rev:
        y = np.pad(y, ((0, 0), (0, 3 * fs)))                   # export adds a 3 s tail when REVERB is on
        wet = np.array([fftconvolve(y[c], IR[c])[: y.shape[1]] for c in range(2)])
        y = (1 - rev / 100) * y + rev / 100 * wet
    if cho: y = (1 - cho / 100) * y + cho / 100 * chorus(y)
    return y

# an 8-bar beat at 140: kick, 808, snare, a sung-style lead in the middle; hats a little left/right; one wide pad
n = int(8 * 4 * beat * fs); T = lambda s: np.arange(int(s * fs)) / fs
def place(hits, snd, bt=beat):
    y = np.zeros(n)
    for b in hits:
        i = int(round(b * bt * fs)); s = snd[: n - i]; y[i:i + len(s)] += s
    return y
kick = np.sin(2 * np.pi * np.cumsum(55 + 110 * np.exp(-T(.25) * 30)) / fs) * np.exp(-T(.25) * 12)
b808 = np.tanh(1.5 * np.sin(2 * np.pi * 49 * T(1.2))) * np.exp(-T(1.2) * 2.2) * .7
snare = (.5 * np.sin(2 * np.pi * 190 * T(.2)) + sosfilt(butter(4, 1500, 'hp', fs=fs, output='sos'), rng.standard_normal(int(.2 * fs))) * .4) * np.exp(-T(.2) * 20)
hat = sosfilt(butter(4, [6000, 12000], 'bp', fs=fs, output='sos'), rng.standard_normal(int(.05 * fs))) * np.exp(-T(.05) * 90) * .35
tt = np.arange(n) / fs; f0 = 220 * 2 ** (np.round(2 * np.sin(2 * np.pi * tt / (4 * beat))) / 12)
lead = sum(np.sin(2 * np.pi * k * np.cumsum(f0 * (1 + .004 * np.sin(2 * np.pi * 5.5 * tt))) / fs) / k ** 1.3 for k in range(1, 12)) * .12
pad = [sosfilt(butter(2, [300, 2500], 'bp', fs=fs, output='sos'), rng.standard_normal(n)) * .05 for _ in range(2)]   # different noise per side = wide
mid = place([b * 4 for b in range(8)] + [b * 4 + 2.5 for b in range(8)], kick) + place([b * 4 for b in range(0, 8, 2)], b808) \
      + place([b * 4 + o for b in range(8) for o in (1, 3)], snare) + lead
hl, hr = place([i / 2 for i in range(64)], hat * 1.2), place([i / 2 for i in range(64)], hat * .8)
mix = np.array([mid + hl + pad[0], mid + hr + pad[1]]); mix *= 10 ** (-1 / 20) / np.abs(mix).max()

def corr(y): return np.corrcoef(y[0], y[1])[0, 1]
def mono_loss(y):                                   # level of the mono fold (L+R)/2 vs the stereo average
    m = (y[0] + y[1]) / 2; return 10 * np.log10(np.mean(m ** 2) / np.mean((y[0] ** 2 + y[1] ** 2) / 2))

print(f"Test mix: 8 bars at 140 BPM, 48 kHz stereo, kick/808/snare/lead centred, hats slightly L/R, one wide pad")
print("\n1) Correlation and mono fold-down (1 = identical sides, 0 = unrelated; mono loss: level of (L+R)/2 vs stereo)")
print(f"   {'setting':38}{'corr':>7}{'mono loss':>11}")
rows = [("Original (no slowing)", dict()), ("TIME 80, no FX", dict(time=80)),
        ("TIME 80 + REVERB 30 (default on)", dict(time=80, rev=30)), ("TIME 80 + REVERB 55 (Holy Tuss amount)", dict(time=80, rev=55)),
        ("TIME 80 + CHORUS 30 (default on)", dict(time=80, cho=30)), ("TIME 80 + CHORUS 100", dict(time=80, cho=100)),
        ("TIME 88 + REVERB 40 + CHORUS 18", dict(time=88, rev=40, cho=18))]
for name, kw in rows:
    y = halfscrew(mix, **kw); print(f"   {name:38}{corr(y):7.3f}{mono_loss(y):8.2f} dB")

# 2) the reverb on its own: a centred (mono) source through the wet path only
src = np.array([mid, mid]) / np.abs(mid).max() * .5
wet = halfscrew(src, time=80, rev=100)
print(f"\n2) Reverb return alone, centred source, TIME 80, REVERB 100 (wet only): corr {corr(wet):.3f}, "
      f"mono loss {mono_loss(wet):.2f} dB (the dry centre loses {mono_loss(varispeed(mid,.8)[None].repeat(2,0)):.2f} dB)")

# 3) chorus flutter: steady centred sine tones; Hilbert envelope over 4 s, 5th-95th percentile swing in dB
from scipy.signal import hilbert
def swing(sig):
    e = 20 * np.log10(np.abs(hilbert(sig))[fs:-fs // 2] + 1e-12); lo, hi = np.percentile(e, [5, 95]); return hi - lo
tt5 = np.arange(5 * fs) / fs
print("\n3) Chorus flutter: level swing of a steady centred tone (5th-95th percentile over 4 s)")
print(f"   {'tone':>9}{'setting':>14}{'left speaker':>14}{'mono fold':>11}")
for f in (39.2, 500, 2000):
    tone = .3 * np.sin(2 * np.pi * f * tt5)
    for c in (0, 30, 100):
        y = halfscrew(np.array([tone, tone]), cho=c)
        print(f"   {f:7.1f}Hz{('CHORUS ' + str(c)) if c else 'no chorus':>14}{swing(y[0]):11.1f} dB{swing((y[0] + y[1]) / 2):8.1f} dB")
print("   (39.2 Hz = an 808 on G1, 49 Hz, slowed to TIME 80)")
d = 2 * 0.0035
print(f"\n   Chorus sides differ by up to {d*1000:.1f} ms, so the mono fold's first notch sweeps down to {1/(2*d):.1f} Hz at the 1.5 Hz rate")

Reading the numbers

Slowing didn’t move the needle. The original and the TIME 80 version both read 0.995 and lost 0.01 dB in mono. If your slowed version folds to mono badly, the slowdown isn’t the reason.

Reverb makes the mono version drier, not broken. REVERB at 30 took the correlation to 0.927, and at 55, Holy Tuss’s amount, to 0.628, with 0.90 dB lost in mono. The wet signal on its own read −0.099, which means unrelated rather than fighting. In mono it lost 3.46 dB while the dry centre lost nothing, so the reverb sits about 3.5 dB further back on a phone than on headphones. On a washed-out slowed + reverb mix that can even help. If the space is the song, check it in mono before you decide the amount.

The chorus is where it gets strange. At 100 the correlation fell to 0.109 and the mix lost 2.56 dB in mono. Each speaker on its own held a steady note steady, within 0.1 dB, because a single delayed copy only bends pitch. Folded to mono, the two sides’ copies interfere: they’re up to 7.0 ms apart, so a notch sweeps through the spectrum as low as 71.4 Hz, and a 500 Hz note swung 32.9 dB, a 2 kHz note 21.5 dB. That’s the underwater flutter.

At the default 30, the flutter moves into each speaker. Mixing 70% dry with 30% moving copy makes them beat against each other, so a 500 Hz note swung 7.9 dB in the left speaker but only 0.7 dB in mono, where the opposite sweeps partly cancel out. The chorus works on the whole mix, 808 included, and a 39.2 Hz 808 note, a G1 slowed to TIME 80, swung 6.3 dB in each speaker. If your slowed 808 throbs on headphones, look at the chorus before the compressor.

A mono check for a slowed version

  1. Fold to mono once before you export. Your DAW’s mono button or a utility plugin on the master. Listen to the hook, not the intro.
  2. If it flutters in mono, pull the chorus down first. At 100 the mono fold swung by tens of dB. Set it by ear with mono on, then switch back.
  3. If the 808 throbs, keep the chorus off it. Slow the 808 and the melody as separate stems with the same TIME, PITCH and WOW, chorus only the melody, and they still line up, because the same settings move every file the same way from its first sample.
  4. If mono sounds too dry, that’s the reverb losing about 3.5 dB. Decide whether the stereo version is too wet before you add more. Timing the tail to the new tempo often fixes the wash without touching the amount.
  5. Read the correlation. The analyzer on this site shows it, and how to read a phase correlation meter explains the scale. CoProducer flags readings under about 0.2, which our CHORUS 100 render would have tripped.
  6. Then play it off a phone. The phone-speaker check covers what happens to the low end there.
Mono doesn’t show you the slowdown. It shows you the effects. When the slowed version sounds wrong on one speaker, turn the effects down one at a time before you touch the speed.
Does slowing a song make it less mono compatible?
Not by itself. Varispeed does the same thing to both sides. In our test the original and a TIME 80 version both read 0.995 correlation and lost 0.01 dB in mono.
Why does my slowed and reverb sound dry in mono?
The reverb’s left and right sides are mostly unrelated, so they add up quieter than the centred dry signal. In our test the reverb lost 3.46 dB in mono while the dry centre lost nothing.
Is chorus bad for mono?
Heavy chorus can be. At CHORUS 100 a steady 500 Hz note swung 32.9 dB in the mono fold. At 30 it swung only 0.7 dB in mono, but 7.9 dB in each speaker.
What phase correlation is safe for a slowed version?
Near +1 is fully mono safe and around 0 is wide but usually fine. CoProducer flags readings under about 0.2. Our CHORUS 100 render read 0.109.

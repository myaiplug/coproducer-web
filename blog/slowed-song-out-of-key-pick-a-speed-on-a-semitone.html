Slowed version out of key? Pick a speed that lands on a semitone

NoDAW Labs · Lacquer Vol. 06

If a slowed version has to stay in a real key, pick a speed that lands on a whole semitone, like 84.09% for three semitones down, instead of a round number like 85%. Tape-style slowing drops pitch by the same ratio as tempo, and round speeds land between notes. In our test 85% left the note 18.6 cents sharp of the semitone below it, and 80% left it 13.7 cents sharp. On its own nobody notices. The moment you sing, play or tune anything over the slowed beat, you hear it.

You slow the beat to 85%, it sounds right, and you open a new session to write over it. You set Auto-Tune to the new key, lay down some keys, and the hook feels a little sour. Nothing is broken. The sample still sounds like itself. The beat just isn’t in that key anymore. It’s sitting somewhere between two keys.

Why round speeds land between keys

Tape-style slowing (varispeed) plays the same samples back slower, so the pitch drops by exactly the same ratio as the tempo. Notes are spaced by ratio too: each semitone is a step of about 5.95% in speed. Round percentages almost never line up with those steps. We checked it in key_speed_check.py: an A3 note at 220 Hz, slowed with 4-point Hermite interpolation (the same kind HalfScrew’s HQ mode uses), then read with an FFT peak finder against equal-tempered notes at A = 440 Hz.

# Where a slowed song's notes land: round speeds vs speeds that land on a whole semitone.
# Synthetic A3 note (220 Hz + harmonics), slowed tape-style with 4-point Hermite interpolation
# (the same interpolator HalfScrew's HQ mode uses), then measured with an FFT peak finder.
import numpy as np
fs = 48000
NOTES = ["A", "A#", "B", "C", "C#", "D", "D#", "E", "F", "F#", "G", "G#"]

def tone(f0=220.0, dur=4.0):
    t = np.arange(int(fs * dur)) / fs
    return sum(np.sin(2 * np.pi * k * f0 * t) / k for k in range(1, 6)) * 0.2

def hermite_slow(y, speed):                      # varispeed: read the samples back at `speed`
    pos = np.arange(0, len(y) - 3, speed); i = pos.astype(int); f = pos - i
    y0, y1, y2, y3 = y[np.maximum(i - 1, 0)], y[i], y[i + 1], y[i + 2]
    c1 = 0.5 * (y2 - y0); c2 = y0 - 2.5 * y1 + 2 * y2 - 0.5 * y3; c3 = 0.5 * (y3 - y0) + 1.5 * (y1 - y2)
    return ((c3 * f + c2) * f + c1) * f + y1

def f0_of(y):                                     # strongest peak under 300 Hz, parabolic interpolation
    n = 1 << 20; w = np.hanning(len(y)); X = np.abs(np.fft.rfft(y * w, n))
    k = np.argmax(X[: int(300 * n / fs)]); a, b, c = np.log(X[k - 1: k + 2])
    return (k + 0.5 * (a - c) / (a - 2 * b + c)) * fs / n

def nearest(f):                                   # nearest equal-tempered note at A = 440 Hz
    semis = 12 * np.log2(f / 440.0); n = int(round(semis))
    ref = 440.0 * 2 ** (n / 12); return NOTES[n % 12], ref, 100 * (semis - n)

y = tone(); bpm = 140
print(f"Source: A3 at {f0_of(y):.2f} Hz, song at {bpm} BPM. One semitone = a {100*(2**(1/12)-1):.2f}% change in speed\n")
print(f"{'speed':>8} {'shift':>9} {'new BPM':>8} {'A3 now':>9} {'nearest':>8} {'off by':>9} {'beats vs in-tune note':>22}")
rows = [("round", s) for s in (0.95, 0.90, 0.85, 0.80, 0.75, 0.70)] + \
       [("semitone", 2 ** (-n / 12)) for n in (1, 2, 3, 4, 5, 12)]
last = None
for kind, s in rows:
    if kind != last: print(f"-- {kind} speeds"); last = kind
    f = f0_of(hermite_slow(y, s)); name, ref, cents = nearest(f)
    print(f"{100*s:7.2f}% {12*np.log2(s):+7.2f} st {bpm*s:8.2f} {f:7.2f}Hz {name:>8} {cents:+7.1f} c {abs(f-ref):10.2f} per second")

print("\nHalfScrew's TIME and PITCH both play the file back faster or slower (varispeed),")
print("so the export speed is TIME/100 x 2^(PITCH/12):")
for t, p in ((100, -3), (100, -2), (80, 0), (89, 0), (85, 0), (90, -1)):
    r = t / 100 * 2 ** (p / 12)
    print(f"   TIME {t:3d}%  PITCH {p:+d}  -> speed {100*r:6.2f}%  {12*np.log2(r):+6.2f} st  {(12*np.log2(r)-round(12*np.log2(r)))*100:+6.1f} c from a semitone")

Reading the numbers

Round speeds landed 11 to 19 cents off. 85% and 90% were the worst: 18.6 and 17.6 cents sharp of the nearest note, close to a fifth of a semitone. 80% was 13.7 cents sharp, 95% was 11.2 sharp, and 70% went 17.5 cents flat. 75% happened to land within 2.0 cents, only because it’s almost exactly five semitones down.

You hear it as beating, not as a wrong note. At 85% the A3 landed at 187 Hz. The in-tune F# right next to it is 185 Hz, so the two fundamentals wobble against each other twice a second, and the harmonics above them wobble faster. That’s the sour, seasick feeling when a fresh keys part or a tuned vocal goes over a beat that was slowed by a round number.

Semitone speeds landed dead on. 94.39%, 89.09%, 84.09%, 79.37% and 74.92% put the note exactly one to five semitones down, 0.0 cents off, and 50% is exactly an octave. The catch is the tempo: 140 BPM at 84.09% is 117.73 BPM, not a round number.

When it matters, and when it doesn’t

  • It doesn’t matter for a slowed + reverb version of a finished song that people will just play. Pick the speed by feel.
  • It matters when you write a new verse, hook or instrument over a slowed beat, tune a vocal to a key over it, or layer it with in-tune samples, parts or another song in a blend.
  • It matters most with hard tuning. Auto-Tune set to the new key pulls the voice onto in-tune notes while the beat underneath sits 11 to 19 cents away.

  1. Decide by ear how far down you want it, in semitones. Two to four is the usual slowed range. Twelve is true half speed.
  2. Use the matching speed from the table. If your tool wants a ratio, it’s 2 to the power of minus semitones over 12.
  3. Set the new session tempo with its decimals (original BPM × speed), so the grid, the chops and the delays line up.
  4. If you need a round BPM instead, say for a DJ set, keep the round speed and tune the new parts to the slowed beat, not to A440. The script prints how many cents to offset.
  5. Write down the speed you used. The next slowed version on the tape should match it.

In HalfScrew you don’t have to type decimals. Its PITCH knob moves in whole semitones, and like the TIME knob it’s varispeed, so it slows the track along with the pitch. TIME at 100% with PITCH at −3 exports at 84.09% speed, exactly three semitones down. TIME at 85% exports at 85%, 18.6 cents off. If you’d rather stay on TIME, 89% lands within 1.7 cents of two semitones down. The export filename carries the TIME and PITCH you used, so later you’ll know which version you’ve got.

Landing on a semitone fixes the key, not the voice. Varispeed moves the formants with the note, so a vocal three semitones down still sounds bigger and darker. That’s the screwed sound. If the singer has to sound like themselves, that’s a formants job, and if the key can’t move at all, that’s a time-stretch job.
What speed should I slow a song to so it stays in key?
A speed equal to a whole number of semitones: 94.39% (one down), 89.09% (two), 84.09% (three), 79.37% (four), 74.92% (five) or 50% (an octave). In our test each landed 0.0 cents off.
Is a song slowed to 80% still in key?
Not exactly. 80% is 3.86 semitones down, so the song sits 13.7 cents sharp of four semitones down. Alone it sounds fine; against new in-tune parts it beats.
What key is my song after slowing it to 85%?
About three semitones down, plus 18.6 cents sharp. Either use 84.09% to land exactly three semitones down, or tune anything you add 18.6 cents sharp.
What BPM is a slowed song?
The original BPM times the speed. 140 BPM at 84.09% is 117.73 BPM; at 80% it’s 112 BPM.

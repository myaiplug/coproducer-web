Chopping a slowed beat? Cut on the new BPM, not the old one

NoDAW Labs · Lacquer Vol. 06

Chop a slowed beat on the slowed tempo’s grid: the new BPM is the old BPM times the speed, and every chop gets longer by the same factor. In our test a 140 BPM beat at HalfScrew’s TIME 80 became 112 BPM, so a half-bar chop grew from 857.1 to 1071.4 ms. Cut at the old length, the repeat came back 214.4 ms early, more than a 16th note.

You slowed the beat, it sounds right, and now you want the move that makes it chopped and not just slowed: back the phrase up and play it again. The session is still at 140 from when you made the beat, snap is on, you cut half a bar, duplicate it, and the repeat stumbles in like it missed a step.

Nothing is wrong with your ears or your cut. The chop in chopped and screwed is a repeat, a phrase, a beat or a word played twice, and a repeat only works if it lands where the next bar starts. Slowing moved where that is.

The new grid is one multiplication

Tape-style slowing stretches time by the same factor it lowers pitch. Multiply the BPM by the speed and divide every note length by it. In HalfScrew, TIME 80 with PITCH at 0 is a speed of 0.8. Add a PITCH move and the export speed becomes TIME/100 × 2^(PITCH/12), so the tempo changes with it.

To put numbers on it, we wrote chop_grid.py. It prints chop lengths at a few TIME settings, then builds a four-bar beat at 140 BPM with a sustained note underneath, so cuts land mid-wave the way they do in real music. It slows the beat at TIME 80 with HalfScrew’s resampler, ported from its source, WOW at 0. Then it makes the classic repeat, the first half bar played twice before the record carries on, cut once on the old grid and once on the new one, with and without a 5 ms fade.

# Chopping a slowed beat: chop lengths at the slowed BPM, and what happens if you cut on the old grid.
# Slowing = HalfScrew's resampler ported from halfscrew.js resample() (v=44): 4-point Hermite (HQ), WOW 0.
import numpy as np
from scipy.signal import butter, sosfilt
fs = 48000; rng = np.random.default_rng(11)
BPM = 140; beat = 60 / BPM

def hermite(y0, y1, y2, y3, f):
    c1 = 0.5 * (y2 - y0); c2 = y0 - 2.5 * y1 + 2 * y2 - 0.5 * y3; c3 = 0.5 * (y3 - y0) + 1.5 * (y1 - y2)
    return ((c3 * f + c2) * f + c1) * f + y1
def halfscrew_resample(a, ratio):
    n = int(np.ceil(len(a) / ratio)); pos = np.arange(n) * ratio; i0 = np.floor(pos).astype(int); f = pos - i0
    g = lambda k: np.where((k >= 0) & (k < len(a)), a[np.clip(k, 0, len(a) - 1)], 0.0)
    return hermite(g(i0 - 1), g(i0), g(i0 + 1), g(i0 + 2), f)

# 1) chop lengths
print("Chop lengths (ms) at 140 BPM and at HalfScrew TIME settings (PITCH 0, so speed = TIME/100)")
print(f"   {'TIME':>5}{'BPM':>7}{'1/16':>9}{'1/8':>9}{'beat':>9}{'1/2 bar':>9}{'bar':>9}{'beat @48k (samples)':>22}")
for tm in (100, 90, 80, 70, 50):
    bpm = BPM * tm / 100; b = 60 / bpm
    print(f"   {tm:4d}%{bpm:7.1f}{b/4*1000:9.1f}{b/2*1000:9.1f}{b*1000:9.1f}{2*b*1000:9.1f}{4*b*1000:9.1f}{b*fs:22.2f}")

# 2) a 4-bar beat at 140, slowed to TIME 80 (112 BPM)
bars = 4; L = int(round(bars * 4 * beat * fs))
t = lambda sec: np.arange(int(sec * fs)) / fs
def place(hits, sound, n=L, bt=beat):
    y = np.zeros(n)
    for b in hits:
        i = int(round(b * bt * fs)); seg = sound[: n - i]; y[i:i + len(seg)] += seg
    return y
hp = lambda x, fc: sosfilt(butter(4, fc, 'highpass', fs=fs, output='sos'), x)
kick = np.sin(2 * np.pi * np.cumsum(49 + 120 * np.exp(-t(0.25) * 30)) / fs) * np.exp(-t(0.25) * 12)
snare = (0.6 * np.sin(2 * np.pi * 200 * t(0.2)) + hp(rng.standard_normal(int(0.2 * fs)), 1500) * 0.5) * np.exp(-t(0.2) * 22)
hat = sosfilt(butter(4, [6000, 12000], 'bandpass', fs=fs, output='sos'), rng.standard_normal(int(0.05 * fs))) * np.exp(-t(0.05) * 90) * 0.4
pad = 0.15 * np.sin(2 * np.pi * 220 * np.arange(L) / fs)          # a sustained note, so cuts land mid-wave
kicks = [b * 4 + o for b in range(bars) for o in (0, 2.5)]; snares = [b * 4 + o for b in range(bars) for o in (1, 3)]
kick_trk = place(kicks, kick)                                     # kept as its own stem so we can track the kicks
src = kick_trk + place(snares, snare) + place([i / 2 for i in range(bars * 8)], hat) + pad
speed = 0.80; slow = halfscrew_resample(src, speed); slow_k = halfscrew_resample(kick_trk, speed); nb = 60 / (BPM * speed)
print(f"\nSource: {bars}-bar beat at {BPM} BPM ({len(src)/fs:.3f} s). Slowed at TIME 80: {len(slow)/fs:.3f} s = {len(slow)/fs/(4*nb):.3f} bars at {BPM*speed:.0f} BPM")

def onsets(y):
    k = int(0.003 * fs); env = np.sqrt(np.convolve(y ** 2, np.ones(k) / k, 'same'))
    above = env > 0.5 * env.max(); idx = np.flatnonzero(above & ~np.concatenate([[False], above[:-1]]))
    keep = [idx[0]]
    for i in idx[1:]:
        if i - keep[-1] > 0.15 * fs: keep.append(i)
    return np.array(keep) / fs
def fade(seg, ms):
    n = int(ms / 1000 * fs); seg = seg.copy()
    if n: r = np.linspace(0, 1, n); seg[:n] *= r; seg[-n:] *= r[::-1]
    return seg
def screw_repeat(y, chop_len, fade_ms):
    # classic chop: play the first half bar twice, then let the record carry on from where the repeat started
    n = int(round(chop_len * fs)); c = fade(y[:n], fade_ms)
    return np.concatenate([c, c, fade(y, fade_ms)])
def grid_error(k, b):
    ks = onsets(k)                                                             # onsets on the kick stem, same edit applied
    err = (ks - np.round(ks / (b / 2)) * (b / 2)) * 1000                     # vs nearest 8th on the given grid
    return ks, np.abs(err).max()
def splice_jump(y, at):
    i = int(round(at * fs)); return np.abs(np.diff(y[i - 2:i + 2])).max()

print("\nHalf-bar repeat on the slowed file: play the first half bar twice, then carry on (112 BPM grid: half bar = 1071.4 ms)")
print(f"   {'':26}{'chop (ms)':>10}{'fade':>6}{'repeat lands (ms)':>19}{'early by':>10}{'jump at splice':>16}")
for label, chop in (("cut on the old 140 grid", 2 * beat), ("cut on the new 112 grid", 2 * nb)):
    for fms in (0, 5):
        out = screw_repeat(slow, chop, fms); ks = onsets(screw_repeat(slow_k, chop, fms))
        land = ks[ks > 0.1][0] * 1000                     # first kick after the start = the repeated downbeat
        print(f"   {label:26}{chop*1000:10.1f}{fms:4d}ms{land:19.1f}{2*nb*1000 - land:10.1f}{splice_jump(out, chop):16.3f}")
print(f"   (unedited slowed file: typical sample-to-sample step in the music {np.median(np.abs(np.diff(slow))):.3f})")
print(f"   one 16th at 112 BPM = {nb/4*1000:.1f} ms")

# 3) chop at 140 then slow, vs slow then chop at 112
a = halfscrew_resample(screw_repeat(kick_trk, 2 * beat, 5), speed)
b = screw_repeat(slow_k, 2 * nb, 5)
oa, ob = onsets(a), onsets(b)
print(f"\nChop at 140 then slow  vs  slow then chop at 112: lengths {len(a)/fs:.3f} s / {len(b)/fs:.3f} s, "
      f"{len(oa)} / {len(ob)} kicks, largest difference in kick position {np.abs(oa - ob).max()*1000:.2f} ms")

# 4) session tempo with decimals: POTION preset (TIME 100, PITCH -2)
r = 1.0 * 2 ** (-2 / 12); bpm = BPM * r
print(f"\nPOTION preset (TIME 100, PITCH -2): speed {r:.4f}, {BPM} BPM -> {bpm:.2f} BPM")
for sess in (round(bpm), round(bpm, 1), round(bpm, 2)):
    for nbars in (4, 16):
        drift = abs(nbars * 4 * 60 / sess - nbars * 4 * 60 / bpm) * 1000
        print(f"   session at {sess:<7} after {nbars:2d} bars the grid is {drift:6.1f} ms off the audio")

Reading the numbers

Everything got longer by the same factor. At 112 BPM a beat is 535.7 ms instead of 428.6, a half bar 1071.4 instead of 857.1, a bar 2142.9 instead of 1714.3. The four slowed bars were exactly 4.000 bars at 112. Nothing about the beat is off the grid. It’s on a different grid.

The old grid cuts short. A half-bar chop at the 140 length is 857.1 ms. On the slowed file the repeat landed at 857.0 ms, when the bar line was at 1071.4, so it came back 214.4 ms early. That’s more than a 16th at 112, which is 133.9 ms, and it means the repeat lops off the end of the phrase and pulls everything after it early. Cut at the new length, the repeat landed at 1071.3 ms, 0.1 ms off.

Every cut needs a fade. Without one, the splice jumped by 0.132 and 0.080, against a typical step of 0.003 between neighbouring samples in the music. A jump like that is a click. A 5 ms fade took it to 0.001 and 0.000. The fade-in made our onset reading 3.5 ms later, because it softens the very start of the kick under the cut. If a chop that starts on a kick loses its snap, shorten the fade-in on that one cut. Clicks at your edit points has the full story on fades.

Chopping first and slowing after gives you the same thing. We also cut the repeat at 140 and slowed the result. Both versions came out 10.714 s long, with the same 10 kicks, the largest difference in position 0.42 ms. So if your chops are already in the original session, at a nice round tempo, chop there and slow the bounce. The grid scales with it.

Decimals matter. HalfScrew’s POTION preset is TIME 100 with PITCH −2, a speed of 0.8909, which takes 140 to 124.73 BPM. Set the session to 125 and the grid was 16.9 ms off the audio after 4 bars and 67.5 ms after 16. At 124.73 it was 1.0 ms after 16. That’s the same rounding problem as a sample drifting off the grid, just one you made yourself.

A chop session that stays on the grid

  1. Work out the new tempo. Old BPM times the speed. HalfScrew writes t and p into the export name, so night-drive-HalfScrew-t80-p0-w0-mix100.wav is 0.8, and 140 becomes 112.
  2. Set the session to that tempo, decimals included. Your DAW’s grid handles 124.73 fine. A beat at 112 is 25714.29 samples at 48 kHz, so let the grid place the cuts rather than typing sample counts.
  3. Chop a dry, steady file. WOW loads at 25 in HalfScrew and moves the timing a little as well as the pitch, which the wobble essay measured. Set it to 0 for the file you chop, and leave reverb off so you aren’t cutting a tail mid-ring. Add the wobble and the space after the chops are in. Time the tail to the new tempo when you do.
  4. Cut in musical lengths, a beat, half a bar, a bar, at the new tempo, with a short fade on every cut.
  5. Or chop at the original tempo and slow afterwards. Same result, easier numbers.
Write the slowed BPM at the top of the session before you make the first cut. Every chop length follows from that one number.
How do I find the BPM of a slowed beat?
Multiply the original BPM by the speed. A 140 BPM beat at 80% is 112. HalfScrew’s POTION preset (TIME 100, PITCH −2) is a speed of 0.8909, so 140 becomes 124.73.
How long is a chop at the slowed tempo?
Divide the original length by the speed, or work it out from the new BPM. At 112 BPM a beat is 535.7 ms, half a bar 1071.4 ms and a bar 2142.9 ms.
Should I chop before or after slowing?
Either works, as long as the grid moves with the speed. In our test, chopping at 140 and then slowing put every kick within 0.42 ms of slowing first and chopping at 112.
Why do my chops click?
The cut lands mid-wave, so the audio jumps. In our test a bare splice jumped by 0.132 against a typical step of 0.003; a 5 ms fade brought it to 0.001.
